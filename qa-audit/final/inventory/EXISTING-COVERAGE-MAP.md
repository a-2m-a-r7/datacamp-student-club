## Scope and isolation evidence

- `qa-audit/fixes.config.ts:1`: `fix-tests`, localhost `127.0.0.1:3100`, one worker, viewports 1440/768/375 × 900. It rebuilds QA assets; three viewport passes repeat the same scenario, not three distinct functional requirements.

Some tests replace those handlers with Playwright route fixtures; see each row.
- `qa-audit/fix-tests/persisted-platform.ts:11`: in-memory PGlite with migrated public schema, synthetic auth/storage tables, roles and three QA users; `asUser` executes SQL with RLS. Browser Supabase REST/Auth/Storage are custom adapters (`:30` onward), not an actual Supabase network service. Fake sessions are injected. Stored-object bytes are kept in memory. Supports SQL policy/trigger behavior, not real Auth email, OAuth, Storage service limits, or realtime delivery parity.
- `qa-audit/fix-tests/roles.spec.ts:5`: lower-fidelity session helper returns mutable JS records, records outbound writes, and stubs RPCs. Those tests alone cannot establish SQL/RLS persistence.
- `qa-audit/fix-tests/course-growth.spec.ts:10`: separate PGlite/REST adapter. Actual DB assertions are useful; Supabase Auth/HTTP service behavior still adapted.
- `qa-audit/playwright.config.ts:15`: legacy `tests/` config uses `TEST_BASE_URL` if supplied or generic localhost:3000 dev server. This suite is not intrinsically isolated by the QA host overrides; executor must explicitly choose an isolated target. Do not point it at production as part of this new isolated pass.
- Node API tests set fake environment keys and intercept `globalThis.fetch`, restoring it in finally. They invoke actual handler logic but external responses/Auth semantics are fixtures.
- `qa-audit/course-growth-postgres.mjs:16`: embedded PostgreSQL binds loopback35432, 80 max connections, client pool20. Its 1000-user benchmark is queued requests through **20 real connections**, not 1000 simultaneous browser/video sessions. It creates disposable directories and invokes migrations; parent must decide/run it explicitly.
