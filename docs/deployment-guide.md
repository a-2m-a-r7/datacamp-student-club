# Deployment checklist and authorization

Current audit branch: tester-final. Do not push, merge, publish Sites or deploy Vercel until the owner approves the concrete final report. QA resources are separately authorized. The production project is excluded from this audit's tests and schema operations.

1. Use Node 22 or newer and npm 10 or newer. Run npm ci from the committed package-lock.json; do not mix package managers. Copy .env.example locally and configure a dedicated nonproduction Supabase project before testing.
2. For an empty Supabase project, apply the sorted canonical schema migrations from 20261013 onward, including 20261017065319_serialize_form_sheet_sync.sql. Historical earlier migrations include sample content. Inspect SQL first; never reset or seed an existing project. Confirm 34 RLS flags, explicit grants, four bucket policies and 16 Realtime entries. Create the first Auth identity normally, confirm its email, then have the owner perform a narrowly scoped trusted administrator assignment. Local/QA migration approval does not authorize production application.
3. Configure public Supabase URL/key and canonical site URL in the correct environment. Keep SUPABASE_SERVICE_ROLE_KEY, Google secrets, Gemini key and Sheets private key server-only. No secret uses a VITE_ prefix. .env.example contains names/blank credential values only.
4. Configure Supabase Auth site/redirect allowlists for the exact environment. Google Web OAuth redirects to that project's /auth/v1/callback. The application returns to /auth/callback. Drive uses the site's /api/courses/drive with drive.file and an owner-consented connection. Keep QA Google clients/project separate from production.
5. Enable Drive API, Sheets API and eligible Gemini free-tier usage in the selected project. Sheets prefers the form creator's existing drive.file connection and creates an owner-held response spreadsheet without new OAuth scopes. A service account with actual spreadsheet/Drive access remains a fallback; consumer Drive creation may be denied. Never invent credentials. Google testing-mode refresh tokens may expire after seven days; QA may stay in Testing, while production publishing/verification is an explicit owner operation. GEMINI_COURSE_MODEL and GEMINI_CHAT_MODEL can override the supported default alias; verify its availability in the selected free tier.
6. Run npm run build, npm run lint and explicit tsc --noEmit. lint currently runs TypeScript; there is no ESLint script. Run the isolated full browser, Node, SQL, hosted service and clean-clone gates. Read results instead of trusting historical filenames.
7. After approval, set environment variables on Vercel, review the full diff and pending SQL against the target project's history, then deploy the approved commit. Verify security/cache headers, actual auth redirect, UI member/admin access, upload/download and a read-only smoke of every route. Do not claim a live smoke before deployment.

Piston is optional. C++/Java/Go/Rust need a separate Piston-compatible server and public endpoint configured as VITE_PISTON_API_URL. Keep execution credentials off the client; apply isolation, quotas and timeouts on that service. Unsupported remote execution must display a clear unavailable result. Current local browser runtimes are tested separately.

Free plans do not establish 1000 concurrent video sessions. Review Supabase connection/Realtime limits, Vercel function limits and Drive bandwidth/quotas against an approved bounded staging load plan. No paid upgrade is authorized.
